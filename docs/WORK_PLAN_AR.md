# ملف العمل التنفيذي | خطوة (Khotwa)

**تاريخ البدء:** 28 أكتوبر 2026  
**وثيقة المرجع:** SRS v1.3  
**هدف الإصدار الأول (MVP):** تطبيق عربي متكافئ على Android وiOS ينجز مسار ملف طالب مجهّل → تقييم أولي → خطة مسودة ومراجعة → أنشطة → جلسات → تقدم → تقارير، مع الخصوصية والضوابط البشرية.

## الحالة الحالية

**جاهز مبدئيًا للتطوير:** هيكل Flutter عربي، نموذج ملفات مجهلة، عناصر بطاقات التقييم الست، إدخال النتائج ومراجعتها، تخزين محلي مشفر أولي للبيانات التجريبية، اختبارات قواعد.  
**غير منفذ بعد:** تسجيل دخول فعلي، أدوار وصلاحيات، خادم/API، قاعدة بيانات الإنتاج، مزامنة/معالجة تعارضات، توليد خطط/أنشطة بالذكاء الاصطناعي، جلسات ورسوم وتقارير Word/PDF، تطبيق إدارة الموافقات الرسمية، سجل تدقيق، الاختبارات الميدانية والبناء النهائي على الجهازين.

## مراحل التنفيذ (ترتيب عمل، لا تواريخ ملزمة)

| المرحلة | مخرجات فعلية | معيار انتهاء المرحلة |
|---|---|---|
| 0. تهيئة المشروع | Flutter SDK، مولد المنصتين، عمل الشاشات والاختبارات، مراجعة النسخة المرجعية | `flutter analyze` و`flutter test`، فتح التطبيق على Android، تجهيز تشغيل iOS على Mac |
| 1. أمان البيانات والحسابات | دخول واستعادة الحساب، RBAC، موافقات، سياسات الاحتفاظ، التخزين المشفر الإنتاجي | لا يمكن وصول غير مخوّل؛ تخزين محمي؛ قرارات موقع البيانات موثقة |
| 2. ملفات الطلبة والتقييم | نماذج إدخال موجهة، مسودات التقييم المؤتمتة الحفظ، سلالم المهارة، سجل نسخ القالب والتقييم | كل مسار التقييم يُستكمل دون اتصال ويُحفظ بعد الإغلاق؛ اعتماد المختصة محفوظ ومؤرشف |
| 3. الخطة والأنشطة | تكامل AI عبر Backend، حذف/تقليل البيانات قبل الإرسال، مسودة مع مصدر العناصر ومراجعة واعتماد صريح | اختبارات تمنع اختلاق بيانات أو تشخيص أو اعتماد تلقائي؛ نشاط بأدوات متاحة فقط |
| 4. الجلسات والتقدم | إدخال لاحق/دفعي، متابعة حالات الجلسة، حساب دقة صحيح/كلي، أعمدة التقدم | المزامنة تستعيد جلسات دون تكرار والتقارير لا تختلط بمؤشرات التقييم |
| 5. التقارير | ثلاثة أنواع Word/PDF، علامة مؤسسة، رموز فريدة وتقارير منفصلة | تصدير عربي سليم، من دون اسم، ورقم تسلسلي وحيز إضافة الاسم يدويًا |
| 6. الإطلاق على النظامين | اختبار هواتف/أجهزة لوحية، Android وiOS، سياسة خصوصية، TestFlight / Play | اجتياز المسارات الكاملة والتكافؤ الوظيفي والأمان على النظامين قبل النشر |

## أول دفعة مهام مقترحة (Sprint أول)

- [ ] تشغيل `scripts/bootstrap.ps1` (Windows) أو `scripts/bootstrap.sh` (Mac/Linux).
- [ ] تشغيل فحوص Dart/Flutter، ومعالجة أي تعارض SDK أو تعديل API مطلوب.
- [ ] فحص بطاقة 1 وبطاقة 6 على شاشات صغيرة وكبيرة مع العربية RTL.
- [ ] مراجعة التطابق بين البنود التعليمية وبين ملحق (ب) بالتعاون مع المختصة.
- [ ] اعتماد قائمة الأجهزة وإصدارات Android/iOS الدنيا بالاختبار.
- [ ] حسم موقع الاستضافة وموافقات نقل البيانات عبر الحدود ونص الموافقة.
- [ ] اعتماد نموذج الخطة الرسمي الفارغ، وسلم التصحيح غير المعياري.
- [ ] تصميم API مصادقة وتخزين وتزامن بعد حل قيود حفظ البيانات.

## تعريف الاكتمال لأي مهمة (Definition of Done)

1. متطلب محدد من SRS موثق برمز FR/NFR.
2. واجهة عربية واضحة ودعم RTL وإتاحة الوصول.
3. تحقق من عدم إضافة اسم أو تاريخ ميلاد كامل أو بيانات صحية.
4. اختبار آلي للقواعد الأساسية واختبار يدوي للحالات السلبية.
5. عدم فقدان البيانات عند الإغلاق أو انقطاع الشبكة بعد اكتمال طبقة المزامنة.
6. نجاح متكافئ على Android وiOS بعد تجهيز بيئة البناء للمنصتين.
7. لا يعتمد أي تفسير تربوي أو خطة منتجة آليًا دون قرار المختصة.
