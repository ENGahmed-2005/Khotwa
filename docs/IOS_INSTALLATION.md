# تثبيت نسخة خطوة على iPhone

ملف `Khotwa-iOS-UNSIGNED.ipa`، عند نجاح مسار البناء، يحتوي تطبيق iPhoneOS حقيقيًا مبنيًا بوضع Release لمعمارية arm64. الحزمة **غير موقّعة ولا تُثبت مباشرة على iPhone**. نجاح البناء لا يثبت الاختبار على جهاز فعلي أو اكتمال MVP.

المشروع الحالي لا يتضمن فريق Apple أو شهادة توقيع بمفتاحها الخاص أو ملف provisioning مخصصًا له. لا يُنشر هذا المسار إلى App Store أو TestFlight، ولا يستخدم حساب Apple أو ينشئ اشتراكًا مدفوعًا.

## ما يلزم لحزمة قابلة للتثبيت

لتوزيع تجريبي على أجهزة مسجلة عبر مسار Apple، يلزم App ID مطابق لـ `org.khotwa.khotwa`، وشهادة توقيع مناسبة مع مفتاحها الخاص، وملف provisioning يطابق التطبيق وأجهزة الاختبار. يُضبط الفريق والتوقيع في Xcode على macOS، ثم تُبنى وتُصدَّر حزمة موقّعة بالطريقة المناسبة. توضح [وثائق Apple لتوزيع التطبيق على أجهزة مسجلة](https://developer.apple.com/documentation/xcode/distributing-your-app-to-registered-devices) هذه المتطلبات وخطوات تسجيل الأجهزة والتوزيع.

يوضح [دليل Flutter الرسمي لبناء iOS وإصداره](https://docs.flutter.dev/deployment/ios) إعداد الفريق والتوقيع في Xcode، وبناء archive وIPA، واختيار طريقة تصدير تجريبية عند توفر بيانات التوقيع. يُحفظ أي ملف توقيع أو كلمة مرور في مخزن أسرار مناسب؛ لا يُضاف إلى Git أو التطبيق أو لقطات الشاشة.

## الخادم وبيانات الاختبار

عنوان API المضمّن مذكور في `BUILD_METADATA.json`. إذا كان `https://localhost:3000` فهو عنوان للبناء فقط؛ localhost على iPhone يشير إلى الهاتف نفسه. يلزم عنوان HTTPS صالح يمكن للهاتف الوصول إليه وإعادة البناء بهذا العنوان قبل اختبار الدخول والمزامنة على الهاتف. يظل استخدام بيانات الطلاب الحقيقية معطلًا إلى حين اعتماد سياسات المشروع.

يحتوي المستودع مسار `.github/workflows/native-preview.yml` للبناء على macOS مع Flutter 3.47.9 عند دفع ملفات التطبيق أو المسار نفسه إلى فرع `feat/fnd-02-foundation`. ويدعم التشغيل اليدوي عندما يكون متاحًا في إعدادات GitHub. يشغّل حل التبعيات المقفلة والتنسيق والتحليل وجميع اختبارات Flutter قبل البناء، ويتحقق من حزمة iPhoneOS ومعمارية arm64 وسلامة ZIP، ثم يرفق SHA-256 وبيانات البناء. لا تُعتبر هذه الفحوص دليل توقيع أو تثبيت.
